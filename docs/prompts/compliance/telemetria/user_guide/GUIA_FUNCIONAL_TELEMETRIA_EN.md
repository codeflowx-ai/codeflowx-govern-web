## 🎯 WHAT IS TELEMETRY AND ANALYTICS?

Telemetry and Analytics is a system for **monitoring and analyzing events** generated by AI OS (Artificial Intelligence Operating System) components. Its objective is to provide complete visibility into the behavior, performance, and usage of AI systems in production.

### 🎯 Main Purpose

The Telemetry system enables:

1. **Real-Time Monitoring:** Visualization of events and metrics from AI components
2. **Performance Analysis:** Aggregated KPIs on latency, costs, tokens, and events
3. **Advanced Search:** Event search by multiple criteria (content, component, project, dates)
4. **Component Analysis:** Detailed statistics per AI component
5. **Temporal Analysis:** Visualization of monthly metrics and trends
6. **Governance:** Detection of bias, toxicity, PII, and secrets in events

---

## 🚀 WHAT IS TELEMETRY USED FOR?

### 1. **For Operational Monitoring**

- **Complete Visibility:** View all events generated by AI components
- **Aggregated KPIs:** Consolidated metrics (total events, costs, tokens, average latency)
- **Component Analysis:** Compare performance across different components
- **Problem Detection:** Identify components with high latency or elevated costs

### 2. **For Cost Optimization**

- **Cost Analysis:** Visualize total costs and per component
- **Token Usage:** Monitor token consumption per component
- **Opportunity Identification:** Detect components with unusually high costs
- **Trends:** Analyze cost evolution over time

### 3. **For Performance Analysis**

- **Latency:** Monitor component response times
- **Throughput:** Analyze volume of processed events
- **Comparison:** Compare performance across components
- **Trends:** Identify performance degradation over time

### 4. **For Governance and Compliance**

- **Bias Detection:** Identify events with detected biases
- **Toxicity:** Detect toxic content in events
- **PII (Personally Identifiable Information):** Identify personal data in events
- **Secrets:** Detect secrets or exposed credentials in events
- **Automatic Categorization:** The system automatically calculates:
  - **Compliance Status (complianceStatus):** PASS, WARNING, REVIEW_REQUIRED, VIOLATION, CRITICAL_VIOLATION
  - **Risk Level (riskLevel):** LOW, MEDIUM, HIGH, CRITICAL
  - **Compliance Category (complianceCategory):** GDPR, SECURITY, LEGAL
  - **Issue Tags (issueTags):** bias_critical, pii_exposure, secret_leak, toxicity_high, etc.

### 5. **For Search and Auditing**

- **Content Search:** Search for events containing specific text in payload
- **Component Search:** Filter events by specific component
- **Project Search:** View events from all components in a project
- **Temporal Filters:** Analyze events in specific date ranges

## 📊 MAIN TELEMETRY COMPONENTS

### 1. **Telemetry Dashboard**

Centralized view showing:
- **Main KPIs:** Total events, total costs, total tokens, average latency, number of components
- **Date Filters:** Select date range for analysis
- **Statistics by Component:** Table with aggregated metrics per component
- **Charts:** Visualization of trends and distributions
- **Navigation:** Quick access to search and monthly analysis

### 2. **Event Search**

Complete system for searching and filtering events:
- **Content Search:** Search text in payload and metrics
- **Multiple Filters:** By component UUID, agent, event type, severity
- **Temporal Filters:** Start and end date range
- **Governance Filters:** Bias, toxicity, PII, secrets detected
- **Compliance/Security Filters:**
  - **Compliance Status:** PASS, WARNING, REVIEW_REQUIRED, VIOLATION, CRITICAL_VIOLATION
  - **Risk Level:** LOW, MEDIUM, HIGH, CRITICAL
  - **Compliance Category:** GDPR, SECURITY, LEGAL
  - **Issue Tags:** Filter by specific tags (bias_critical, pii_exposure, etc.)
- **Pagination:** Navigation through result pages
- **Detailed Visualization:** Complete detail page for each event with full payload, metrics, and analysis

### 3. **Monthly Analysis**

Temporal analysis dashboard:
- **Monthly Metrics:** Total events, costs, tokens, average latency per month
- **Trend Charts:** Visualization of monthly evolution
- **Year Selector:** Analyze different years
- **Comparison:** Compare metrics between months

### 4. **Statistics by Component**

Detailed analysis per component:
- **Aggregated Metrics:** Total events, average latency, total tokens, total costs
- **Comparison:** View all components in a table
- **Temporal Filters:** Analyze components in specific date ranges

## 🔄 TYPICAL WORKFLOW

### Scenario 1: Daily Monitoring

1. **Dashboard Access**
   - Navigate to Governance → Telemetry → Dashboard
   - View main KPIs for the period (last 30 days by default)

2. **Component Analysis**
   - Review component statistics table
   - Identify components with high latency or elevated costs
   - Compare performance across components

3. **Trend Analysis**
   - Review distribution charts
   - Identify patterns or anomalies

### Scenario 2: Problem Investigation

1. **Problem Identification**
   - Detect component with anomalous metrics in the dashboard
   - Or receive alert about specific event

2. **Event Search**
   - Go to Search page
   - Filter by component UUID or project
   - Apply date filters for the problem period
   - Search by specific content if known

3. **Event Analysis**
   - Review found events
   - Navigate to detail page of relevant events
   - View complete payload, metrics, and analysis results
   - Review automatically calculated compliance/security fields:
     - Compliance status and risk level
     - Compliance category and issue tags
   - Verify governance detections (bias, toxicity, PII, secrets)

4. **Decision Making**
   - Identify root cause of the problem
   - Determine necessary corrective actions

### Scenario 3: Cost Analysis

1. **Total Cost Analysis**
   - Go to Dashboard
   - View total cost KPI
   - Adjust date range if necessary

2. **Analysis by Component**
   - Review component statistics table
   - Identify components with highest cost
   - Analyze cost/tokens/events relationship

3. **Temporal Analysis**
   - Go to Monthly Analysis
   - View month-to-month cost evolution
   - Identify trends and spikes

4. **Optimization**
   - Identify optimization opportunities
   - Compare costs between similar components
   - Plan cost reduction actions

### Scenario 4: Governance and Compliance Auditing

1. **Search for Events with Problems**
   - Go to Search page
   - Use compliance/security filters:
     - **Compliance Status:** VIOLATION or CRITICAL_VIOLATION
     - **Risk Level:** HIGH or CRITICAL
     - **Category:** GDPR, SECURITY or LEGAL as needed
     - **Tags:** Filter by specific tags (pii_exposure, secret_leak, bias_critical, etc.)
   - Or use traditional governance filters:
     - Bias detected
     - Toxicity detected
     - PII detected
     - Secrets detected

2. **Event Analysis**
   - Review events that triggered detections
   - Navigate to detail page of each event
   - View complete payload, metrics, and analysis results
   - Review automatically calculated fields (complianceStatus, riskLevel, complianceCategory, issueTags)

3. **Documentation**
   - Export or document relevant events
   - Generate reports if necessary
   - Use compliance/security fields for classification and prioritization

## 📈 METRICS AND KPIs

### Main KPIs

1. **Total Events**
   - Total number of telemetry events in the period
   - Indicator of activity volume

2. **Total Cost (USD)**
   - Sum of costs from all events
   - Calculated from cost metrics per event

3. **Total Tokens**
   - Sum of tokens consumed in all events
   - Indicator of AI model usage

4. **Average Latency (ms)**
   - Average response time of components
   - Performance indicator

5. **Number of Components**
   - Quantity of unique components that generated events
   - Coverage indicator

### Metrics per Component

For each component the following are calculated:
- **Total Events:** Number of events generated
- **Average Latency:** Average response time
- **Total Tokens:** Sum of tokens consumed
- **Total Cost:** Sum of costs in USD

## 🔍 SEARCH CAPABILITIES

### Available Search Criteria

1. **Content Search**
   - Searches text in payload JSONB and metrics
   - Useful for finding specific events

2. **Filter by Component UUID**
   - Filter events from a specific component
   - Identify component by UUID

3. **Filter by Agent**
   - Filter by `agentExternalId`
   - Useful for tracking events from specific agents

4. **Filter by Event Type**
   - Filter by `eventType` (e.g., INTERACTION_COMPLETED, ERROR, etc.)

5. **Filter by Severity**
   - INFO, WARN, ERROR, DEBUG
   - Useful for finding error events

6. **Temporal Filters**
   - Start date
   - End date
   - Allows analysis in specific ranges

7. **Governance Filters**
   - **Bias Checked:** Events where bias was checked
   - **Toxicity Checked:** Events where toxicity was checked
   - **PII Detected:** Events with detected personal data
   - **Secret Detected:** Events with detected secrets

8. **Compliance/Security Filters**
   - **Compliance Status (complianceStatus):** PASS, WARNING, REVIEW_REQUIRED, VIOLATION, CRITICAL_VIOLATION
   - **Risk Level (riskLevel):** LOW, MEDIUM, HIGH, CRITICAL
   - **Compliance Category (complianceCategory):** GDPR, SECURITY, LEGAL
   - **Issue Tag (issueTag):** bias_critical, bias_high, bias_medium, pii_exposure, secret_leak, toxicity_critical, toxicity_high, toxicity_medium, compliance_issue

### Filter Combination

All filters can be combined for precise searches:
- Example: Events from a specific component in a date range with PII detected
- Example: Error events from a project in the last month

## 🎯 COMMON USE CASES

### Case 1: "How much does my AI system cost this month?"

1. Go to Telemetry Dashboard
2. Adjust date filters to current month
3. View "Total Cost (USD)" KPI

### Case 2: "Which component has the highest latency?"

1. Go to Telemetry Dashboard
2. Review component statistics table
3. Sort by average latency (descending)
4. Identify component with highest latency

### Case 3: "Search all errors from the last day"

1. Go to Event Search
2. Select severity "ERROR"
3. Set start date: yesterday
4. Set end date: today
5. Click "Search"

### Case 4: "Analyze trends from the last year"

1. Go to Monthly Analysis
2. Select current year
3. Review trend charts
4. Compare months

### Case 5: "Find events with personal data"

1. Go to Event Search
2. Use filter "Compliance Category" = "GDPR" or activate "PII" checkbox
3. Set date range
4. Click "Search"
5. Review found events
6. Navigate to detail page of relevant events to view complete information

### Case 6: "Identify critical security events"

1. Go to Event Search
2. Set filters:
   - **Compliance Status:** CRITICAL_VIOLATION
   - **Risk Level:** CRITICAL
   - **Compliance Category:** SECURITY
3. Set date range
4. Click "Search"
5. Review found events
6. Navigate to detail page for complete analysis

## 🔐 SECURITY AND PRIVACY CONSIDERATIONS

### Sensitive Data

- Events may contain sensitive information in payloads
- The system automatically detects PII and secrets
- It is recommended to review events with detections before sharing

### Data Access

- Only authorized users can access telemetry
- Data is protected by authentication and authorization
- It is recommended to limit access to sensitive data
